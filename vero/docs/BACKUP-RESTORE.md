# VERO — دليل النسخ الاحتياطي والاستعادة

> بياناتك ملكك بالكامل. لا تُرسل إلى أي جهة خارجية.

---

## ما الذي تحتويه النسخة؟

ملف JSON مضغوط (`vero-backup-YYYY-MM-DD…json.gz`) يحوي **كل** جداول التطبيق:

الشركة · المستخدمون · الإعدادات · السيارات · العمال · الحاويات · رموز QR ·
الأجهزة وارتباطاتها · أكواد التفعيل · جلسات ونقاط المسار · الزيارات ومحاولات المسح ·
عقود SLA · التقارير · سجل العمليات

**غير مشمول:** ملفات الشعار المرفوعة (احفظها من `vero_storage`) وكلمات المرور الأصلية (مخزَّنة مجزَّأة، وهذا هو الصحيح).

---

## النسخ من اللوحة

**النسخ الاحتياطي → إنشاء نسخة الآن**، ثم **تنزيل**.

⚠ **نزّل الملف إلى خارج السيرفر.** النسخة الموجودة على نفس السيرفر لا تحميك من فقدانه.

### النسخ التلقائي

مفعَّل افتراضيًا كل 24 ساعة (`AUTO_BACKUP_ENABLED=1`). تظهر بنوع «تلقائية».

---

## النسخ من سطر الأوامر

### نسخة VERO (محمولة)

```bash
curl -X POST https://vero.company.example/v1/backups \
  -H "Authorization: Bearer $TOKEN"
```

### نسخة pg_dump (كاملة على مستوى قاعدة البيانات)

```bash
docker compose exec -T db pg_dump -U vero -Fc vero > vero-$(date +%F).dump
```

الاستعادة منها:

```bash
docker compose exec -T db pg_restore -U vero -d vero --clean --if-exists < vero-2026-09-04.dump
```

> **أيهما أستخدم؟** نسخة VERO محمولة وتُستعاد من اللوحة بضغطة. نسخة `pg_dump` أقرب للنسخ التقليدي وأسرع للقواعد الضخمة. **خذ الاثنتين** — لا تتعارضان.

## نسخة كاملة للسيرفر (موصى بها أسبوعيًا)

```bash
#!/usr/bin/env bash
# /opt/vero/backup.sh
set -euo pipefail
STAMP=$(date +%F-%H%M)
OUT=/opt/vero-backups
mkdir -p "$OUT"

cd /opt/vero
docker compose exec -T db pg_dump -U vero -Fc vero > "$OUT/db-$STAMP.dump"
docker run --rm -v vero_storage:/data -v "$OUT":/out alpine \
  tar czf "/out/storage-$STAMP.tar.gz" -C /data .
cp .env "$OUT/env-$STAMP.bak"        # ⚠ يحوي الأسرار — احمِ صلاحياته

find "$OUT" -name '*.dump' -mtime +30 -delete
find "$OUT" -name '*.tar.gz' -mtime +30 -delete
echo "تمت النسخة: $STAMP"
```

```bash
chmod 700 /opt/vero/backup.sh
sudo crontab -e
# كل يوم 2:30 فجرًا
30 2 * * * /opt/vero/backup.sh >> /var/log/vero-backup.log 2>&1
```

⚠ انسخ `$OUT` دوريًا إلى **تخزين خارج السيرفر**.

## الاستعادة

> ⚠ **الاستعادة إجراء مدمّر**: تُمحى كل البيانات الحالية وتُستبدل بمحتوى الملف.
> تُنفَّذ داخل معاملة واحدة: إما تنجح كاملة أو لا يتغيّر شيء.

1. **خذ نسخة من الحالة الراهنة أولًا** — حتى لو كانت تالفة.
2. النسخ الاحتياطي → **استعادة من ملف**.
3. اختر الملف واكتب كلمة **«استعادة»** للتأكيد.
4. راجع جدول السجلات المستعادة، ثم أعد تحميل اللوحة.

### ماذا يحدث بعد الاستعادة؟

| البند | النتيجة |
|---|---|
| الحاويات ورموز QR | تعود كما كانت — **الملصقات المطبوعة تظل صالحة** |
| الزيارات وسلسلة الإثبات | تعود كاملة وسليمة (تحقّق من «الزيارات») |
| المستخدمون وكلمات المرور | تعود كما كانت وقت النسخ |
| أجهزة العمال | تعود، لكن أي جهاز فُعِّل **بعد** النسخ لن يعمل → أعد تفعيله |
| سجل العمليات | يعود إلى لقطة وقت النسخ + عملية الاستعادة نفسها |

بعد الاستعادة تحقّق من:
- `GET /health` يرجع `setupCompleted: true`
- «الزيارات» تعرض **«سلسلة الإثبات سليمة»**
- عدّادات الرئيسية معقولة

---

## مفتاح توقيع QR — الأهم

`QR_SIGNING_KEY` في `.env` هو ما يجعل ملصقاتك المطبوعة صالحة.

| الحالة | النتيجة |
|---|---|
| استعادة بيانات + **نفس المفتاح** | ✅ كل الملصقات تعمل |
| استعادة بيانات + **مفتاح مختلف** | ❌ **كل الملصقات المطبوعة تصبح غير صالحة** وتلزم إعادة طباعتها |

> احتفظ بنسخة من `QR_SIGNING_KEY` في مدير كلمات مرور أو خزنة. **لا يمكن استرجاعه إن ضاع.**

## اختبار التعافي (مرتين سنويًا على الأقل)

نسخة لم تُختبر ليست نسخة.

```bash
# 1) شغّل نسخة اختبار على منفذ مختلف
mkdir -p /opt/vero-test && cd /opt/vero-test
cp -r /opt/vero/{docker-compose.yml,backend,admin} .
cp /opt/vero/.env .env
sed -i 's/^API_PORT=.*/API_PORT=4100/;s/^ADMIN_PORT=.*/ADMIN_PORT=3100/' .env
docker compose -p vero-test up -d

# 2) استعد النسخة من اللوحة على المنفذ 3100
# 3) تحقّق من الأعداد وسلسلة الإثبات
# 4) نظّف
docker compose -p vero-test down -v
```
