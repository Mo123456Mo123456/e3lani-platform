# VERO — كل زيارة لها إثبات.

> **Every Visit Has a Proof.**
> نظام مستقل لشركات ومؤسسات النظافة، يثبت أن كل حاوية أو نقطة خدمة زارها العامل فعليًا —
> بالوقت والموقع والعامل والسيارة — باستخدام جوال العامل ورمز QR فقط، بلا أي أجهزة ميدانية إضافية.

---

## نموذج المنتج

| البند | القرار |
|---|---|
| نموذج التسليم | **نسخة مستقلة لكل شركة** — لا SaaS، ولا اشتراك شهري |
| الاستضافة | **Self-Hosted** على سيرفر الشركة عبر Docker Compose |
| قاعدة البيانات | مستقلة تمامًا داخل نفس الـstack |
| الاعتماد على البائع | **لا يوجد**: لا License Server، لا حساب مركزي، لا API إجباري |
| تشغيل بلا إنترنت خارجي | ✅ (عدا خرائط الأساس، وهي قابلة للاستبدال بنمط داخلي) |

بعد التسليم تصبح الشركة مسؤولة عن: السيرفر، الاستضافة، الدومين، شهادة TLS،
حسابات المتاجر (Apple / Google Play)، وأي تطوير مستقبلي.

```
vero/
├── backend/     VERO API      — Fastify + TypeScript + PostgreSQL/PostGIS
├── admin/       لوحة الإدارة  — Next.js 15 + RTL + MapLibre

├── docs/        الوثائق والأدلة
└── docker-compose.yml
```

| الطبقة | التقنية | لماذا |
|---|---|---|
| API | Fastify + TypeScript | سريع، خفيف، وتحقّق صارم من المدخلات |
| قاعدة البيانات | PostgreSQL 16 + PostGIS 3 | حسابات جغرافية حقيقية بالأمتار على سطح الأرض |
| اللوحة | Next.js 15 (App Router) | RTL عربي، بناء standalone صغير |
| الخرائط | MapLibre + OpenStreetMap | مجاني وبلا مفتاح؛ قابل للاستبدال بنمط مدفوع |
| الجوال | Expo / React Native | بناء لأندرويد وiOS من مصدر واحد |
| التخزين المحلي | SQLite | لا تُفقد عملية عند انقطاع الشبكة |
| التقارير | PDFKit + ExcelJS | PDF عربي رسمي وExcel كامل، بلا خدمات خارجية |

## التشغيل السريع

```bash
cp .env.example .env

# ولّد الأسرار الثلاثة وضعها في .env
echo "POSTGRES_PASSWORD=$(openssl rand -base64 24)"
echo "JWT_SECRET=$(openssl rand -hex 32)"
echo "QR_SIGNING_KEY=$(openssl rand -hex 32)"

docker compose up -d --build
```

ثم افتح `http://localhost:3000` وأكمل **معالج الإعداد**.

📘 التفاصيل الكاملة في [`docs/INSTALL.md`](docs/INSTALL.md).

## كيف يعمل النظام؟

```
1. كل حاوية لها QR فريد وموقّع  →  ملصق مطبوع بشعار الشركة
2. العامل يصل ويمسح الرمز       →  التطبيق يلتقط GPS والوقت
3. الخادم يتحقق ويقرّر           →  Verified | Suspicious | Invalid
4. الإدارة ترى النتيجة مباشرة    →  لوحة + خريطة + تقارير SLA
```

### رمز QR الموقّع

```
vero1.<رقم الحاوية>.<nonce عشوائي>.<HMAC-SHA256>
```

الرمز **ليس** رقم الحاوية. توقيعه بمفتاح `QR_SIGNING_KEY` الخاص بنسختك يمنع تصنيع ملصق صالح من خارج النظام.

### سلسلة الإثبات (Proof Chain)

كل زيارة تحمل تجزئة مرتبطة بتجزئة الزيارة السابقة:

```
proof_hash = SHA256(prev_hash ‖ bin ‖ nonce ‖ lat ‖ lon ‖ ts ‖ worker ‖ vehicle ‖ device ‖ uuid)
```

أي تعديل مباشر على قاعدة البيانات يكسر السلسلة ويظهر فورًا عبر `GET /v1/scans/chain/verify`.

### منع التكرار اليومي

زيارة معتمدة واحدة لكل حاوية في اليوم، مفروضة بفهرس فريد جزئي في قاعدة البيانات.
المسح المتكرر يُحفظ للتدقيق ولا يُحتسب. عند منتصف الليل بتوقيت الشركة تعود كل الحاويات
تلقائيًا إلى «لم تتم خدمتها» — بلا أي وظيفة مجدولة، لأن الحساب يعتمد على `service_day`.

### كشف التلاعب

| الإشارة | الشرط |
|---|---|
| `OUT_OF_RANGE` | المسافة تجاوزت نطاق الحاوية |
| `LOW_GPS_ACCURACY` | خطأ الموقع تجاوز الحد المضبوط |
| `IMPLAUSIBLE_SPEED` | سرعة انتقال مستحيلة بين مسحين (مع حد أدنى للإزاحة يمنع الإنذار الكاذب) |
| `ROUTE_MISMATCH` | موقع المسح بعيد عن مسار السيارة المسجَّل |
| `FUTURE/STALE_TIMESTAMP` | ساعة الجهاز غير مضبوطة |

الزيارة المشبوهة **لا تُرفض** — تُحفظ وتُعرض للإدارة لتقرّر.

| البند | كيف |
|---|---|

| سيناريو القبول (26 خطوة) | اختبار آلي واحد من التثبيت حتى الاستعادة |
| ملصقات QR | طُبعت PDF ← رُسّمت 300 DPI ← فُكّت بقارئ zbar ← أُرسل الرمز للـAPI ← رجع `VERIFIED` |
| تقارير PDF العربية | وُلِّدت ورُسّمت وفُحص نصها؛ الشكل والاتجاه والأرقام صحيحة |
| Excel | وُلِّد وأُعيدت قراءته بـExcelJS والتحقق من أوراقه وصفوفه |
| النسخ والاستعادة | مسح كامل للبيانات ثم استعادة، مع بقاء سلسلة الإثبات سليمة |
| لوحة الإدارة | بُنيت وشُغِّلت مقابل الـAPI الحقيقي، وتُصفِّحت بمتصفح فعلي (تسجيل دخول + 9 صفحات) |
| البناء الإنتاجي للـAPI | `tsc` ← `node dist/index.js` ← هجرات + PDF بالخطوط من مسار `dist` |
| البناء الإنتاجي للوحة | `next build` (standalone) ← تشغيل `server.js` مع الأصول |

### ⚠ مكتوب ولم يُنفَّذ في هذه البيئة

| البند | السبب | ما يجب فعله عند التسليم |
|---|---|---|
| `docker compose up --build` | بيئة التطوير هنا تحجب تنزيل طبقات Docker Hub | نفّذه على سيرفر الشركة كخطوة أولى؛ الأمر واحد وموثّق |
| بناء تطبيق الجوال (APK/IPA) | يتطلب حساب Expo/EAS وحسابات المتاجر | `eas build` بحساب الشركة — راجع `docs/INSTALL.md` |
| اختبار الجوال على جهاز حقيقي | لا يوجد جهاز في هذه البيئة | جرّب التفعيل والمسح وقطع الشبكة على جهاز فعلي قبل الاعتماد |

> منطق التطبيق (الطابور المحلي، المزامنة، منع التكرار) مُختبَر بالكامل **من جهة الخادم**
> عبر نفس المسارات التي يستدعيها الجوال (`/v1/sync/scans` و`/v1/sync/route-points`).

## حدود النظام — بصراحة

- **لا يمنع التزوير منعًا مطلقًا.** يمكن نظريًا تصوير الملصق ومسحه من مكان قريب. لذلك توجد
  طبقات متعددة: GPS + مسار السيارة + ربط الجهاز + كشف القفزات + سلسلة الإثبات. هذه تجعل
  التزوير مكلفًا وقابلًا للكشف، لا مستحيلًا.
- **دقة GPS تضعف** بين المباني العالية وداخل الأقبية. النطاق قابل للضبط لكل حاوية.
- **لا تتبّع خارج جلسة العمل** — قرار تصميمي مقصود لحماية خصوصية العامل.
- **خرائط الأساس تحتاج إنترنت** (OpenStreetMap). في شبكة مغلقة استبدلها بنمط داخلي عبر
  `MAP_STYLE_URL`. باقي النظام يعمل بلا إنترنت خارجي بالكامل.
- **تشكيل النص العربي في PDF** منفَّذ داخليًا (أشكال العرض + ترتيب ثنائي الاتجاه مبسّط).
  يغطي العربية القياسية بامتياز؛ الحالات الطباعية النادرة جدًا قد تحتاج ضبطًا.
