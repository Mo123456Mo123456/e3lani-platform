# دليل التشغيل — إعلاني

## المتطلبات

- Node.js ≥ 20.11
- pnpm 9 (`corepack enable && corepack prepare pnpm@9.12.0 --activate`)
- Docker + Docker Compose (للبنية التحتية المحلية)

FFmpeg غير مطلوب يدويًا: عامل الوسائط يستخدم `ffmpeg-static` و`ffprobe-static`.

---

## أولًا: التشغيل المحلي

```bash
pnpm install
cp .env.example .env
pnpm infra:up          # PostgreSQL + Redis + MinIO + إنشاء الحاوية تلقائيًا
pnpm db:deploy         # تطبيق الترحيلات
pnpm db:seed           # البيانات المرجعية + حساب الإدارة + بيانات تجريبية
pnpm dev               # تشغيل كل الخدمات
```

### تشغيل الخدمات منفردة

```bash
pnpm dev:api      # http://localhost:4000/api      (توثيق: /api/docs)
pnpm dev:worker   # عامل الوسائط والمهام الدورية
pnpm dev:web      # http://localhost:3000
pnpm dev:admin    # http://localhost:3001
pnpm dev:mobile   # Expo — امسح رمز QR بتطبيق Expo Go
```

### تشغيل تطبيق الجوال على جهاز حقيقي

الجهاز لا يستطيع الوصول إلى `localhost` الخاص بجهازك، لذلك:

```bash
# استبدل بعنوان جهازك على الشبكة المحلية
export EXPO_PUBLIC_API_URL=http://192.168.1.10:4000/api
export EXPO_PUBLIC_MEDIA_URL=http://192.168.1.10:9000/e3lani-media
pnpm dev:mobile
```

وأضف العنوان نفسه إلى `CORS_ORIGINS` في `.env` ثم أعد تشغيل الـ API.

## ثانيًا: قاعدة البيانات

| الأمر | الوظيفة |
|---|---|
| `pnpm db:migrate` | إنشاء ترحيل جديد بعد تعديل `schema.prisma` |
| `pnpm db:deploy` | تطبيق الترحيلات (يُستخدم في الإنتاج) |
| `pnpm db:seed` | بذر البيانات (آمن للتكرار — لا يستبدل ما عدّلته الإدارة) |
| `pnpm db:studio` | واجهة تصفح البيانات |
| `pnpm --filter @e3lani/database migrate:reset` | حذف كل شيء وإعادة البناء (تطوير فقط) |

البذر لا يستبدل أسعارًا أو إعدادات عدّلها المسؤولون؛ يضيف الناقص فقط.

## ثالثًا: تدفّق الوسائط

1. العميل يطلب `POST /api/media/uploads` ← فحص آلي للنوع والحجم ← يعيد رابط رفع موقّعًا.
2. العميل يرفع الملف مباشرة إلى التخزين بـ `PUT`.
3. العميل يستدعي `POST /api/media/uploads/complete` ← يتحقق الخادم من وصول الملف ← يجدول المعالجة.
4. عامل الوسائط:
   - **الصور:** تصحيح الدوران، إزالة البيانات الوصفية، ٣ مقاسات WebP، صورة نائبة صغيرة.
   - **الفيديو:** فحص المدة (رفض ما يتجاوز ٦٠ ثانية)، نسختا 720p/480p بـ H.264 مع `faststart`، صورة مصغّرة تلقائية.
5. عند فشل الفحص الآلي: يُعلَّم الوسيط `FAILED`، ويُرفض أي إعلان مرتبط به تلقائيًا مع إشعار صاحبه — بلا أي تدخّل بشري.

**مهم:** لا بد من تشغيل `pnpm dev:worker` وإلا بقيت الوسائط في حالة `PROCESSING`.

## رابعًا: المهام الدورية

يشغّلها عامل الوسائط تلقائيًا عبر BullMQ:

| المهمة | التوقيت | الوظيفة |
|---|---|---|
| `expire-ads` | كل ساعة | إنهاء الإعلانات المنتهية + تنبيه قبل ٢٤ ساعة |
| `expire-ticker` | كل ساعة | إنهاء شعارات الشريط المنتهية |
| `rollup-stats` | يوميًا ١:٢٠ | تجميع إحصائيات الأمس |
| `cleanup` | يوميًا ٣:٤٠ | حذف الجلسات ورموز التحقق المنتهية والأحداث الأقدم من ١٨٠ يومًا |

## خامسًا: تفعيل الدفع لاحقًا

النظام جاهز بالكامل؛ التفعيل لا يحتاج إعادة بناء:

1. اضبط مفاتيح البوابة في `.env` وغيّر `PAYMENT_PROVIDER`.
2. اضبط الـ Webhook لدى البوابة على `https://api.e3lani.sa/api/payments/webhook`.
3. من لوحة الإدارة ← **الإعدادات**:
   - «تفعيل الدفع» ← مفعّل.
   - «وضع النشر» ← `PAID`.
4. من لوحة الإدارة ← **الأسعار**: راجع القيم وفعّل ما تحتاجه.

عندها تتحول دورة النشر تلقائيًا إلى `مسودة ← بانتظار الدفع ← نشط`،
وتصبح خدمات الترويج قابلة للشراء. لا يُفعَّل أي شيء قبل تأكيد الدفع من البوابة.

## سادسًا: النشر للإنتاج

### الـ API وعامل الوسائط

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm db:deploy
node services/api/dist/main.js            # عملية ١
node services/media-worker/dist/main.js   # عملية ٢
```

يمكن تشغيلهما بـ PM2 أو systemd أو حاويات منفصلة. الـ API عديم الحالة ويقبل التوسع الأفقي؛
عامل الوسائط يمكن تشغيل عدة نسخ منه (BullMQ يوزّع المهام) — مع إبقاء نسخة واحدة فقط
تسجّل المهام الدورية أو الاعتماد على `jobId` الثابت الذي يمنع التكرار.

### الواجهات

- `apps/web` و`apps/admin`: `next build` ثم `next start` أو النشر على Vercel.
- **لوحة الإدارة يجب ألا تكون على نطاق عام مفهرس** — الصفحات تحمل `robots: noindex` وتُقيَّد بشبكة داخلية أو Basic Auth على مستوى المستضيف.

### تطبيق الجوال

```bash
npm install -g eas-cli
cd apps/mobile
eas build --platform all
eas submit --platform ios
```

اضبط `EXPO_PUBLIC_API_URL` و`EXPO_PUBLIC_MEDIA_URL` في ملف `eas.json` لكل بيئة.

## سابعًا: المراقبة والتحقق

| ماذا | كيف |
|---|---|
| صحة الخدمة | `GET /api/health` — يرجع حالة قاعدة البيانات و Redis |
| سجل الإجراءات | لوحة الإدارة ← سجل الإجراءات (كل عملية حساسة مسجّلة) |
| الطوابير | BullMQ يخزّن المهام الفاشلة ٢٤ ساعة للفحص |
| الأخطاء | سجلات JSON منظمة من العامل، وسجلات Nest من الـ API |

## ثامنًا: مشاكل شائعة

| العرض | السبب والحل |
|---|---|
| الوسائط تبقى `PROCESSING` | عامل الوسائط غير مشغّل — `pnpm dev:worker` |
| فشل الرفع من المتصفح | CORS غير مضبوط على حاوية التخزين |
| `إعدادات البيئة غير صالحة` عند الإقلاع | متغير ناقص أو غير آمن — الرسالة تحدد الحقل بدقة |
| لا تصل رسائل التحقق | `OTP_PROVIDER=console` — الرمز في سجل الخادم فقط |
| `PAYMENTS_DISABLED` عند الشراء | الدفع غير مفعّل من لوحة الإدارة (السلوك الصحيح حاليًا) |
| Metro لا يجد حزم المستودع | `pnpm install` من الجذر — إعداد Metro مضبوط للـ monorepo |
