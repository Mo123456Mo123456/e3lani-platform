# دليل التشغيل والمزودين — إعلاني | E3lani

## الغرض والنطاق

توضح هذه الوثيقة حدود النسخة المحلية الحالية، وكيفية تشغيلها وفحصها، وما يجب نقله إلى خدمات حقيقية قبل الإطلاق التجاري. التنفيذ الحالي مناسب للعرض الوظيفي والاختبارات الحتمية؛ ولا يُعد تكاملًا إنتاجيًا لمصادقة العملاء أو تحصيل الأموال أو تخزين الوسائط الدائم.

## أوضاع التشغيل

| الوضع | البيانات | المصادقة والدفع | الاستخدام المناسب |
|---|---|---|---|
| محلي/عرض | `AsyncStorage` على الجهاز | OTP ودفع `sandbox` موثقان | مراجعة المنتج، اختبار الواجهة، وتجارب أصحاب المصلحة |
| خادم التطوير | Express وtRPC، مع MySQL اختياري | بوابات القالب الأساسية | تطوير واجهات الخدمة والمهاجرات والتكاملات |
| إنتاج مستهدف | قاعدة بيانات وتخزين ومراقبة مُدارة | مزودون حقيقيون مع تحقق خادمي | مستخدمون وأموال ووسائط فعلية |

> **قاعدة أمان:** لا تعتمد الواجهة العميلة مصدرًا للحقيقة في الدفع أو الصلاحيات أو قرارات المراجعة. يجب أن يصدر القرار النهائي من الخادم، وأن تُحفظ نتيجته وسجل تدقيقه بصورة ذرية.

## مصفوفة المزودين

| القدرة | التنفيذ الحالي | متطلب الإنتاج | معيار القبول |
|---|---|---|---|
| الدخول | رمز محلي ثابت `123456` | OTP أو OAuth حقيقي مع جلسات آمنة | انتهاء الرمز، تحديد المحاولات، إبطال الجلسة، واختبار الأجهزة المتعددة |
| الدفع | طلب وفاتورة محليان بمزود `sandbox` | بوابة دفع تدعم SAR وwebhooks | تحقق توقيع webhook، منع التكرار، مطابقة المبلغ، واسترداد موثق |
| الوسائط | منتقي جهاز وURI محلي | تخزين كائنات خاص وروابط موقعة | فحص النوع والحجم، إزالة البيانات الوصفية الحساسة، ومعالجة فشل الرفع |
| الإشعارات | قائمة محلية داخل التطبيق | Push عبر مزود موثوق | موافقة المستخدم، رموز أجهزة محدثة، إعادة المحاولة، وإلغاء الاشتراك |
| البيانات | `AsyncStorage` | MySQL عبر مخطط Drizzle الحالي | مهاجرات مراجعة، نسخ احتياطي، استعادة مجربة، وفهارس مراقبة |
| التحليلات | عدادات وأحداث محلية | استقبال خادمي مع مفاتيح إزالة تكرار | منع تضخيم الأحداث، سياسة احتفاظ، ولوحات متسقة زمنيًا |
| الإدارة | أدوار وقرارات محلية | تفويض خادمي لكل إجراء | رفض افتراضي، فصل الصلاحيات، وكتابة سجل تدقيق غير قابل للتجاوز |

## متغيرات البيئة

لا يحتاج وضع العرض المحلي إلى هذه القيم. عند تفعيل الخادم أو مزودي الإنتاج، أضف الأسرار من لوحة **Settings → Secrets** ولا تحفظها في Git.

| المتغير | النطاق | الاستخدام |
|---|---|---|
| `DATABASE_URL` | الخادم | اتصال MySQL المستخدم بواسطة Drizzle |
| `JWT_SECRET` | الخادم | توقيع أو حماية بيانات الجلسة |
| `OAUTH_SERVER_URL` | الخادم | عنوان خدمة المصادقة |
| `OWNER_OPEN_ID` | الخادم | تعريف مالك التطبيق في تكامل المصادقة |
| `VITE_APP_ID` | الخادم | معرف التطبيق لدى بوابة المصادقة |
| `BUILT_IN_FORGE_API_URL` | الخادم | عنوان القدرات المدمجة عند استخدامها |
| `BUILT_IN_FORGE_API_KEY` | الخادم | اعتماد القدرات المدمجة عند استخدامها |
| `EXPO_PUBLIC_API_BASE_URL` | العميل | عنوان API الصريح؛ يشتق الويب عنوان التطوير عند غيابه |
| `EXPO_PUBLIC_OAUTH_PORTAL_URL` | العميل | بوابة بدء OAuth |
| `EXPO_PUBLIC_OAUTH_SERVER_URL` | العميل | عنوان خدمة OAuth المتاح للعميل |
| `EXPO_PUBLIC_APP_ID` | العميل | معرف التطبيق العام |
| `EXPO_PUBLIC_OWNER_OPEN_ID` | العميل | معرف المالك العام عند الحاجة |
| `EXPO_PUBLIC_OWNER_NAME` | العميل | اسم المالك المعروض عند الحاجة |

المتغيرات ذات بادئة `EXPO_PUBLIC_` تصبح متاحة داخل حزمة العميل، ولذلك **يُمنع وضع الأسرار فيها**. أما مفاتيح الدفع والتخزين الخاصة فيجب أن تبقى على الخادم، حتى لو احتاج العميل إلى معرف عام للمزود.

## ترتيب التحويل إلى مزودين حقيقيين

ابدأ بالمصادقة والتفويض الخادميين لأن بقية العمليات تعتمد هوية موثوقة. بعد ذلك فعّل قاعدة البيانات والمهاجرات، ثم تخزين الوسائط، ثم الدفع والتحقق من webhooks، وأخيرًا الإشعارات والتحليلات. حافظ خلال الانتقال على واجهات المجال الحالية، لكن استبدل تنفيذ المخزن المحلي بطبقة استعلامات وخدمات دون تغيير قواعد التسعير ودورة الحياة المختبرة.

| المرحلة | بوابة الخروج المطلوبة |
|---|---|
| الهوية والصلاحيات | جلسات قابلة للإبطال، حماية مسارات الإدارة، واختبارات رفض لكل دور |
| قاعدة البيانات | مهاجرات ناجحة على نسخة مرحلية، نسخة احتياطية، وتجربة استعادة |
| الوسائط | رفع مباشر آمن، معالجة انقطاع الشبكة، وحذف مرتبط بدورة حياة الإعلان |
| الدفع | webhook موقع، idempotency، مطابقة الهللات، وفاتورة مرتبطة بطلب واحد |
| الإطلاق | مراقبة أخطاء، تنبيهات، سياسة خصوصية، شروط استخدام، وخطة تراجع |

## تشغيل وفحص الإصدار

نفّذ من جذر المشروع:

```bash
pnpm check
pnpm lint
pnpm test
pnpm build
npx expo export --platform web --output-dir .expo-export
```

نجاح الأوامر شرط للإصدار، لكنه لا يستبدل الاختبار اليدوي على جهاز iOS وAndroid حقيقيين. اختبر خصوصًا اختيار الصور والفيديو، الأذونات، الروابط الخارجية، لوحة المفاتيح، تكبير النص، VoiceOver/TalkBack، الشبكات البطيئة، واستعادة التطبيق بعد إغلاقه.

## النسخ الاحتياطي والمراقبة

في وضع الإنتاج، فعّل نسخًا احتياطية دورية لقاعدة البيانات مع اختبار استعادة، وسياسة احتفاظ منفصلة للوسائط وسجلات التدقيق. راقب أخطاء API، فشل الرفع، زمن معالجة webhook، اختلاف الطلبات والمدفوعات، حجم طابور المراجعة، وفشل الإشعارات. تجنب تسجيل أرقام الجوال أو رموز المصادقة أو روابط الوسائط الموقعة في السجلات.

## قائمة اعتماد الإصدار

| الفحص | المطلوب قبل الإطلاق التجاري |
|---|---|
| وضع الاختبار | إزالة رمز OTP الثابت وتعطيل تأكيد الدفع التجريبي خارج بيئة العرض |
| المزودون | مفاتيح إنتاج محمية، حدود معدلات، timeouts، وإعادة محاولات مضبوطة |
| المتاجر | نصوص الأذونات، سياسة الخصوصية، لقطات شاشة، وتصنيف المحتوى |
| الوصول | اختبار قارئ الشاشة وتكبير النص والتباين على أجهزة فعلية |
| البيانات | موافقة واحتفاظ وحذف حساب وبيانات وفق السياسة المعتمدة |
| الاستجابة للحوادث | مالك واضح، قناة تنبيه، إجراء تعطيل مزود، ونقطة تراجع مجربة |
