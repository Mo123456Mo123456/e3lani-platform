# كوكب يولد أمامك | A Planet Born Before You

**عالمك، قرارك، أثر لا ينتهي.**

منصة محاكاة عربية/إنجليزية تعرض كوكبًا إجرائيًا ثلاثي الأبعاد يتطور عبر محرك Ticks
حتمي. يستطيع المستخدم تحليل عنصر، موازنته، اختبار مساراته المستقبلية، اختيار إقليم
البداية، ثم إدخاله إلى العالم ومشاهدة الأحداث والروابط السببية الناتجة.

> الحالة الحالية **مرحلة أساس تشغيلية** وليست المنصة الإنتاجية الكاملة. تعمل تجربة
> الكوكب والمحاكاة والمساهمة واللقطات محليًا وتحفظ في `AsyncStorage`. يظهر محلل
> الأفكار بوضوح بصفته Sandbox محليًا؛ لا يدّعي استخدام AI خارجي. أما قاعدة البيانات
> الحالية ومسارات الحساب القديمة فتنتمي إلى المنتج السابق ولم تُحوّل بعد إلى مخطط
> الكوكب. راجع [وثيقة المعمارية](./docs/living-planet-architecture.md) للحدود الدقيقة.

## تشغيل تجربة الكوكب

```bash
pnpm install
pnpm dev
```

افتح واجهة الويب، ثم:

1. دوّر الكوكب وقرّبه وانقر على إقليم.
2. اختر طبقة بيانات من الشريط العلوي.
3. اضغط «ابدأ إضافة جديدة» واختر فئة.
4. اكتب فكرة؛ مثال: `شجرة عملاقة تمتص التلوث وتضيء في الليل لكنها تحتاج إلى ماء كثير`.
5. راجع Structured Output والمزايا والمخاطر وتعديلات التوازن.
6. شغّل 64 مسارًا مستقبليًا ثم أكد الإضافة.
7. شغّل الزمن وتابع الانتشار والأحداث واللقطات.

## Quality commands

```bash
pnpm check
pnpm lint
pnpm test
pnpm build
npx expo export --platform web --output-dir .expo-export
```

The simulation is deterministic: the same seed and command sequence produce the same world
state and event history. Core outcomes are algorithmic; a future LLM adapter may explain
existing events, but must not invent simulation results.

تبقى الشاشات والمخططات التالية في المستودع أثناء التحويل المرحلي، لكنها ليست جزءًا

## حالة المشروع

| البند | الحالة الحالية |
|---|---|
| المنصات | iOS وAndroid وWeb عبر Expo SDK 54 |
| اللغة | العربية RTL افتراضيًا والإنجليزية LTR |
| التخزين التشغيلي | محلي عبر `AsyncStorage` مع بوابة تحميل وخطأ وإعادة محاولة |
| المصادقة | OTP تجريبي موثق؛ الرمز `123456` |
| الدفع | مزود `sandbox` موثق؛ لا توجد حركة مالية حقيقية |
| قاعدة البيانات | مخطط MySQL/Drizzle جاهز، وغير مستخدم لتدفقات الواجهة المحلية حاليًا |
| الجودة | TypeScript وESLint وVitest وبناء الخادم وتصدير Expo ناجحة[2] |

## التشغيل المحلي

يتطلب المشروع Node.js و`pnpm`. من جذر المشروع شغّل:

```bash
pnpm install
pnpm dev
```

يشغّل الأمر خادم API وMetro معًا. ويمكن تشغيل كل جزء منفصلًا عبر `pnpm dev:server` و`pnpm dev:metro`. لا يحتاج وضع العرض المحلي إلى قاعدة بيانات أو مفاتيح مزودين خارجيين.

### تجربة التدفقات التجريبية

استخدم أي رقم جوال صالح بطول لا يقل عن ثمانية محارف، ثم أدخل رمز الاختبار `123456`. عند إنشاء إعلان، يعرض التطبيق السعر والضريبة والإضافات قبل الانتقال إلى الدفع. زر **تأكيد دفع تجريبي** ينقل الطلب إلى المراجعة فقط، ولا ينفذ عملية مالية.

## الانتقال إلى الإنتاج

لا ينبغي تحويل أعلام الواجهة أو اسم المزود فقط. يتطلب الإطلاق الحقيقي نقل القرارات الحساسة إلى الخادم، والتحقق من إيصالات الدفع عبر webhook موثوق، ورفع الوسائط إلى تخزين خاص، وتطبيق مصادقة فعلية وصلاحيات خادمية، وحفظ سجل التدقيق في قاعدة البيانات. يوضح [دليل التشغيل والمزودين][3] ترتيب الربط ومتغيرات البيئة وضوابط الإطلاق.

عند اعتماد النسخة، استخدم زر **Publish** في واجهة إدارة المشروع بعد وجود نقطة استعادة. تتولى عملية النشر بناء الحزمة المناسبة، بما فيها APK عند اختياره، بدل تنفيذ بناء Android يدويًا داخل بيئة التطوير.
