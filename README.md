# إعلاني | E3lani

**إعلاني** منصة إعلانات مرئية للأفراد والبراندات والمتاجر، مبنية كتطبيق Expo متعدد المنصات مع خادم Node وواجهات tRPC وقاعدة MySQL عبر Drizzle. يدعم المنتج العربية RTL افتراضيًا والإنجليزية، ويهدف إلى فصل المنشور المجاني في صفحة المعلن عن توزيعه الإعلاني في الخلاصة.[1]

> المستودع الخاص [`e3lani-platform`][2] هو **مصدر الحقيقة الوحيد للشفرة**. تبقى قاعدة البيانات والتخزين السحابي والخوادم والأسرار وبيانات المستخدمين خدمات منفصلة ولا تُحفظ داخل GitHub.

## الحالة الحالية

النسخة الموسومة `pre-production-review` هي خط أساس ما قبل الإنتاج. يتضمن المشروع مخططًا مركزيًا، وخط وسائط موقّعًا للصور والفيديو، وواجهات خادم، وتطبيق Expo. لا تزال بعض تدفقات المنتج تعتمد على `AsyncStorage`، كما أن المصادقة والدفع يحتاجان استكمال مزودي الإنتاج؛ لذلك لا تُوصف النسخة الحالية بأنها جاهزة للإطلاق التجاري.[1] [3]

| المجال | التنفيذ الحالي |
|---|---|
| العميل | Expo SDK 54، React Native 0.81، Expo Router، TypeScript، NativeWind |
| الخادم | Express وtRPC وZod وجلسات OAuth الأساسية |
| البيانات | MySQL وDrizzle مع مهاجرات وبذور وفحص حالة غير متلف |
| الوسائط | تذاكر رفع قصيرة العمر، تخزين كائنات، تحقق من النوع والحجم، وثلاث نسخ للصور |
| الاختبارات | Vitest وTypeScript وExpo ESLint وبناء Node وتصدير Expo Web |
| حالة الدفع | معطل إنتاجيًا حتى اكتمال Payment Provider Adapter وWebhook موثوق |

## بنية المشروع

| المسار | المسؤولية |
|---|---|
| `app/` | شاشات ومسارات Expo Router للجوال والويب |
| `components/` | المكونات المشتركة ومكونات المنتج |
| `lib/` | عميل tRPC، الحالة، الترجمة، ومنطق رفع الوسائط |
| `server/` | خادم Express وواجهات tRPC وخدمات البيانات والتخزين |
| `drizzle/` | المخططات والمهاجرات وسجل Drizzle |
| `shared/` | العقود والسياسات المشتركة بين العميل والخادم |
| `scripts/` | البذور وتحديث سياسة الوسائط وفحوص قاعدة البيانات |
| `tests/` | اختبارات الوحدات والأمان والتكامل |
| `docs/` | المتطلبات والتشغيل وسياسة Git وأدلة التحقق |

## المتطلبات

استخدم Node.js 22 و`pnpm` 9. يحتاج التشغيل الكامل إلى MySQL متوافق مع `DATABASE_URL`. يمكن تشغيل Metro والواجهة دون بعض الخدمات، لكن التدفقات المركزية لن تعمل كاملًا دون قاعدة البيانات والخادم.

```bash
git clone git@github.com:Mo123456Mo123456/e3lani-platform.git
cd e3lani-platform
corepack enable
pnpm install --frozen-lockfile
cp config/environment.example .env
pnpm dev
```

يشغّل `pnpm dev` خادم API وMetro معًا. للتشغيل المنفصل استخدم `pnpm dev:server` و`pnpm dev:metro`.

## متغيرات البيئة

ابدأ من `config/environment.example` وانسخه محليًا إلى `.env`، ولا تحفظ `.env` في Git. كل متغير يبدأ بـ`EXPO_PUBLIC_` يصبح جزءًا من حزمة العميل، ولذلك يجب ألا يحتوي سرًا.

| المجموعة | المتغيرات الرئيسية |
|---|---|
| قاعدة البيانات | `DATABASE_URL` |
| الجلسات وOAuth | `JWT_SECRET`, `OAUTH_SERVER_URL`, `OWNER_OPEN_ID`, `VITE_APP_ID` |
| التخزين والقدرات الخادمية | `BUILT_IN_FORGE_API_URL`, `BUILT_IN_FORGE_API_KEY` |
| العميل | `EXPO_PUBLIC_API_BASE_URL` ومتغيرات OAuth العامة |
| وضع الخلاصة | `FEED_ACCESS_MODE` |
| الدفع | `PAYMENT_ENABLED`, `PAYMENT_PROVIDER`, `PAYMENT_WEBHOOK_SECRET` |

## قاعدة البيانات

بعد ضبط `DATABASE_URL` شغّل المهاجرات والبذور والفحص:

```bash
pnpm db:push
pnpm db:seed
pnpm db:media-policy
pnpm db:verify
```

يجب مراجعة SQL قبل تطبيقه على بيئة مشتركة، وأخذ نسخة احتياطية قبل أي تغيير بنيوي. لا ينشئ CI بيانات إنتاج ولا يشغّل مهاجرات على قاعدة حقيقية.

## التخزين والوسائط

ينفذ `server/storage.ts` واجهة التخزين الخادمية، بينما يصدر `server/media-service.ts` تذاكر رفع قصيرة العمر ويتحقق من الملكية والحجم والنوع قبل تثبيت الأصل في قاعدة البيانات. لا تضع مفاتيح التخزين في متغيرات `EXPO_PUBLIC_*`، ولا تحفظ ملفات المستخدمين في Git. يحتاج التشغيل خارج بيئة Manus إلى تنفيذ تخزين متوافق مع العقد نفسه أو مزود S3 خاص بالخادم.[3]

## أوضاع الخلاصة

يضبط `FEED_ACCESS_MODE` السلوك المستهدف مركزيًا:

| القيمة | السلوك |
|---|---|
| `PROFILE_ONLY` | النشر في صفحة المعلن فقط، دون توزيع تلقائي في الرئيسية. |
| `FREE_LAUNCH` | توزيع مجاني مؤقتًا بلا شاشة دفع أو نجاح مالي وهمي. وهو الوضع الافتراضي المستهدف للنسخة الأولية. |
| `PAID_ONLY` | يتطلب التوزيع طلب دفع مؤكدًا ومراجعة قبل بدء مدة الظهور. |

إلى أن تكتمل طبقة الإعدادات المركزية في فرع `feature/free-launch-mode`، لا يكفي تغيير المتغير وحده لإثبات السلوك الإنتاجي؛ يجب أن يصدر قرار الخادم من الإعداد المركزي وتغطيه اختبارات API.

## تفعيل الدفع مستقبلًا

يبقى `PAYMENT_ENABLED=false` و`PAYMENT_PROVIDER=disabled` افتراضيًا. لا يُفعّل الدفع بتغيير الواجهة فقط. يتطلب التفعيل Adapter خادميًا، وWebhook متحققًا من التوقيع، وIdempotency، ومطابقة المبلغ والعملة، وربط فاتورة بطلب واحد، واختبارات فشل واسترداد وسجل تدقيق.[3]

## التشغيل على المنصات

| المنصة | الأمر | ملاحظة |
|---|---|---|
| Web | `pnpm dev:metro` | يفتح Expo Web في وضع التطوير. |
| Android | `pnpm android` | يحتاج محاكيًا أو جهازًا وبيئة Expo مناسبة. |
| iOS | `pnpm ios` | يحتاج macOS/Xcode أو جهازًا عبر Expo Go. |
| QR | `pnpm qr` | يولد رمز اتصال بخادم Metro الحالي. |

لإنشاء حزمة متجر استخدم مسار Publish/EAS المخصص للبيئة، ولا تحفظ ملفات APK أو AAB أو IPA في Git.

## الاختبارات وبوابة الدمج

```bash
pnpm check
pnpm lint
pnpm test
pnpm build
npx expo export --platform web --output-dir .expo-export
```

يجب أن تنجح هذه الفحوص في GitHub Actions قبل دمج Pull Request. تحتاج التغييرات التي تمس قاعدة البيانات أو المصادقة أو الوسائط إلى اختبارات API وصلاحيات وفشل شبكي مناسبة، وليس اختبارات واجهة فقط.

## Git والمساهمة

`main` للإصدارات المستقرة فقط، و`develop` للتطوير الجاري. تبدأ الميزات من `feature/*` والإصلاحات من `fix/*` والإصلاحات الحرجة من `hotfix/*`. راجع [دليل المساهمة][4] و[سير Git][5] و[سياسة الأمان][6].
