# إعلاني | E3lani

**منصة الإعلانات المرئية لكل شيء**

منصة سعودية للإعلانات المعتمدة على الصور والفيديوهات القصيرة، بتصفح عمودي سريع.
ليست متجرًا إلكترونيًا: لا بيع مباشر، ولا سلة، ولا توصيل، ولا عمولة، ولا مزاد، ولا محادثات، ولا تعليقات.
عندما يعجب المستخدم بإعلان ينتقل مباشرة إلى متجر المعلن أو واتساب أو الاتصال أو الرابط الذي حدده المعلن.

## البنية

```
e3lani/
├─ apps/
│  ├─ mobile           Expo (React Native) + Expo Router — التطبيق الرئيسي
│  ├─ web              Next.js 15 (App Router) — الموقع العام
│  └─ admin            Next.js 15 (App Router) — لوحة الإدارة فقط
├─ services/
│  ├─ api              NestJS — كل منطق الأعمال وواجهات البرمجة
│  └─ media-worker     Node Worker + BullMQ + FFmpeg + sharp
├─ packages/
│  ├─ ui               Tailwind CSS + مكوّنات مشتركة بدعم RTL كامل
│  ├─ database         Prisma (schema + migrations + seed)
│  ├─ types            TypeScript types + Zod schemas
│  ├─ config           الهوية، المدن، الأقسام، الأسعار الافتراضية، RBAC
│  ├─ eslint-config
│  └─ tsconfig
└─ infra/
   └─ docker-compose.yml   PostgreSQL + Redis + MinIO
```

إدارة المستودع بـ **Turborepo + pnpm workspaces**، و**TypeScript** في كل شيء.

## التقنيات

| الطبقة | التقنية |
|---|---|
| قاعدة البيانات | PostgreSQL 16 + Prisma 6 |
| الطوابير والكاش وحد المعدل | Redis 7 + BullMQ |
| التخزين | S3-compatible (MinIO محليًا / S3 أو R2 في الإنتاج) |
| معالجة الوسائط | sharp للصور، FFmpeg للفيديو |
| المصادقة | JWT (وصول + تحديث) + OTP عبر Adapter Pattern |
| المدفوعات | Adapter Pattern (Moyasar / Tap / HyperPay) — معطّلة افتراضيًا |
| الإشعارات | Expo Push (قابل للتبديل) |
| الحماية | Helmet، CORS مضبوط، Rate Limiting بـ Redis، Audit Logs |

## التشغيل السريع

المتطلبات: **Node.js ≥ 20.11**، **pnpm 9**، **Docker** (للبنية التحتية المحلية).

```bash
# 1) تثبيت الاعتماديات
pnpm install

# 2) إعداد متغيرات البيئة
cp .env.example .env

# 3) تشغيل قاعدة البيانات و Redis و MinIO
pnpm infra:up

# 4) إنشاء الجداول وبذر البيانات المرجعية + حساب الإدارة
pnpm db:deploy
pnpm db:seed

# 5) تشغيل كل الخدمات
pnpm dev
```

بعد التشغيل:

| الخدمة | العنوان |
|---|---|
| الـ API | http://localhost:4000/api |
| توثيق الـ API (تطوير فقط) | http://localhost:4000/api/docs |
| الموقع العام | http://localhost:3000 |
| لوحة الإدارة | http://localhost:3001 |
| تطبيق الجوال | `pnpm dev:mobile` ثم امسح رمز QR بتطبيق Expo Go |
| MinIO Console | http://localhost:9001 (`e3lani` / `e3lani-secret`) |

> ملاحظة: عامل الوسائط يحتاج FFmpeg، وهو مضمّن تلقائيًا عبر حزمتَي `ffmpeg-static` و`ffprobe-static` فلا حاجة لتثبيته يدويًا.

## متغيرات البيئة

كل المتغيرات موثّقة في **`.env.example`**، وتُتحقق عند إقلاع الـ API عبر مخطط Zod؛
الخدمة ترفض العمل بإعدادات ناقصة أو غير آمنة. في بيئة الإنتاج ترفض الخدمة الإقلاع إذا:

- كان `OTP_PROVIDER=console` (مزوّد التطوير).
- كان `PAYMENT_PROVIDER=sandbox` مع تفعيل الدفع.
- بقيت أسرار JWT على قيمها الافتراضية.

## حساب الإدارة التجريبي

يُنشأ بواسطة `pnpm db:seed` من قيم `.env` وهو **لبيئة Sandbox فقط**:

```
البريد الإلكتروني : admin@e3lani.sa
كلمة المرور      : E3lani!Admin2026
الدور            : Super Admin
الرابط           : http://localhost:3001/login
```

> **مهم:** غيّر البريد وكلمة المرور في `.env` قبل أي نشر حقيقي. البذر يرفض كلمة مرور أقصر من ١٢ حرفًا في الإنتاج.

كما تُنشأ حسابات مستخدمين تجريبية (فرد/متجر/براند/شركة) وإعلانات ومنشورات وشعارات شريط،
**فقط** عندما `SEED_DEMO_DATA=true` و`NODE_ENV != production`؛ فلا تصل أي بيانات ثابتة إلى الإنتاج.

في وضع التطوير يُطبع رمز التحقق في سجل الخادم (`[تطوير] رمز التحقق للرقم … هو: ####`)
ولا يُعاد أبدًا في استجابة الـ API.

## الخدمات الخارجية والمفاتيح

القائمة الكاملة مع خطوات الربط في **[`docs/EXTERNAL-SERVICES.md`](docs/EXTERNAL-SERVICES.md)**. باختصار:

| الخدمة | إلزامية؟ | المتغيرات |
|---|---|---|
| PostgreSQL | ✅ | `DATABASE_URL` |
| Redis | ✅ | `REDIS_URL` |
| تخزين S3 / MinIO / R2 | ✅ | `S3_*` |
| مزوّد رسائل OTP (تقنيات / يونيفونك / مسجات) | ✅ للإنتاج | `OTP_PROVIDER` + مفاتيح المزوّد |
| بوابة دفع (ميسر / تاب / هايبر باي) | ⏳ عند تفعيل الدفع | `PAYMENT_PROVIDER` + مفاتيح البوابة |
| Expo Push | اختيارية | `EXPO_ACCESS_TOKEN` |

## قواعد المنتج المطبّقة في الكود

- **النشر:** في الوضع المجاني الحالي `مسودة ← نشط` مباشرة بلا مراجعة بشرية. عند تفعيل الدفع تتحول الدورة تلقائيًا إلى `مسودة ← بانتظار الدفع ← نشط` بتبديل إعداد واحد من لوحة الإدارة (`PUBLISHING_MODE`) دون تعديل أي كود.
- **الفحص الآلي فقط أثناء الرفع:** نوع الملف، الحجم، مدة الفيديو، سلامة الحقول، الروابط، المحتوى الممنوع الواضح. المراجعة البشرية تحدث **بعد** النشر عند وجود بلاغ فقط.
- **الأسعار:** لا يوجد أي سعر مكتوب داخل منطق التطبيق. الأسعار مؤرَّخة بإصدارات في `pricing_versions`: كل تغيير يضيف إصدارًا بنطاق سريان ولا يعدّل أو يحذف أي إصدار سابق، مع دعم الجدولة المسبقة والتراجع، ورفض أي إدراج بأثر رجعي.
- **الفوترة:** فاتورة ضريبية بترقيم تسلسلي وضريبة قيمة مضافة تُستخرج من الإجمالي، مع استرداد كلي/جزئي وتسجيل كل محاولة مع بوابة الدفع.
- **الخصوصية (PDPL):** سجل موافقة موثّق بإصداره ووقته، وطلبات تصدير وحذف البيانات الشخصية.
- **المنشورات المجانية:** جداول وخدمات ومسارات منفصلة تمامًا عن الإعلانات، وتظهر فقط داخل صفحة صاحب الحساب.
- **الشريط العلوي:** شعارات فقط، حركة مستمرة لا تتوقف عند اللمس، غير قابل للنقر (لا يحتوي كائن العرض على أي رابط)، وشعار «إعلاني» فاصل أصغر، ولا يتكرر الشعار نفسه مرتين متتاليتين.
- **لا نجاح دفع وهمي في الإنتاج:** مزوّد الدفع التجريبي يرمي استثناءً عند `NODE_ENV=production`.
- **السعر حقل اختياري** في الإعلان، والبريد الإلكتروني اختياري للأفراد ومطلوب للحسابات التجارية.

## الاختبارات

```bash
pnpm test                              # اختبارات الوحدة (٤١ اختبارًا)
pnpm --filter @e3lani/api test:e2e     # اختبارات تكامل على الـ API (تتطلب البنية التحتية)
```

تغطي الاختبارات: توحيد أرقام الجوال، الفحص الآلي للمحتوى والروابط، قواعد إنشاء الإعلان،
شروط الحسابات التجارية، فصل المنشورات عن الإعلانات، صلاحيات الأدوار (RBAC)،
تحويلات الأسعار، ترقيم الصفحات بالمؤشر، عدم تكرار شعارات الشريط، قواعد معالجة الوسائط،
وحماية المسارات الخاصة ولوحة الإدارة.

## النشر للإنتاج

1. جهّز PostgreSQL و Redis وتخزين S3 مُدارًا.
2. اضبط `.env` بقيم حقيقية (أسرار عشوائية طويلة، مزوّد OTP حقيقي).
3. `pnpm build` ثم `pnpm db:deploy`.
4. شغّل `services/api` و`services/media-worker` كعمليتين مستقلتين.
5. انشر `apps/web` و`apps/admin` (Vercel أو أي مستضيف Node).
6. ابنِ تطبيق الجوال بـ `eas build --platform all`.

تفاصيل أوفى في [`docs/RUNBOOK.md`](docs/RUNBOOK.md).
